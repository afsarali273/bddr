bddr / Reports

Reporters

Reporters turn a run into something you can read or feed to another tool. You can use several at once. They all read the same event stream.

Choose reporters

A reporter is written 'name', 'name:outputFile' or ['name', options]. Paths are relative to the config folder.

The reporters

NameOutputUse it for
consoleTerminal. Pretty by default. progress is a compact style.Local runs and CI logs. Options: style, verbose, colors.
htmlOne self-contained file that works offline. Default reports/report.html.People. See HTML report. Options: outputFile, title, logLevel.
junitJUnit XML, one suite per feature. Default reports/junit.xml.CI systems that show test results. A pass after a retry is a flakyFailure. A quarantined failure is skipped.
cucumber-json (or json)Cucumber JSON. Default reports/cucumber.json.Dashboards that read the Cucumber format.
messagesCucumber Messages as NDJSON. Default reports/messages.ndjson.Tools that read Cucumber Messages. Scenarios generated from @data files are left out.
ndjsonEvery event as one JSON line. Default reports/bddr.ndjson.The source of truth. Re-run failed tests, merge runs and build other reports from it. See Event stream.

When several files are merged, later runs win for each scenario. This is how sharded runs and re-runs of failures become one report.

Run history

With history: true bddr keeps a record of each run in .bddr/history. The HTML report uses it for trends, and npx bddr history lists the flakiest and slowest scenarios.
