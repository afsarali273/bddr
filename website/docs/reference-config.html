bddr / Reference

Config options

All options go at the top level of defineConfig, and every one except profiles can be changed for one run with --set.

Specs and steps

OptionTypeDefaultWhat it does
featuresstring or string[]features/**/*.feature, features/**/*.feature.mdSpec globs, relative to the config file.
stepsstring or string[]steps/**/*.{ts,js,mjs}, features/**/*.steps.{ts,js,mjs}Support code: steps, hooks, fixtures, parameter types.
dataDirstringthe config folderFolder for @data: files. With a profile, <dataDir>/<profile>/file is tried first.
languagestring'en'Default Gherkin language.
pluginsarrayPackage names, file paths, [name, options] pairs or plugin objects. See How plugins work.

Selection and values

OptionTypeDefaultWhat it does
tagsstringTag expression applied to every run. Combined with -t using and.
namestringRegular expression on the scenario name.
paramsRecord<string, string>Values for ctx.params. -D overrides.

Execution

OptionTypeDefaultWhat it does
workersnumber1Scenarios running at once.
pool'inline' or 'process''inline'See Worker processes.
groupsRecord<string, GroupConfig>See below and Groups.
defaultMode'parallel', 'serial', 'exclusive'How ungrouped scenarios run.
featureMode'parallel' or 'serial''serial' runs the scenarios of every feature in file order. @parallel opts a feature out.
failFastbooleanfalseStop after the first failed scenario.
strictbooleantruePending, undefined and ambiguous steps fail the run.

Time and retries

OptionTypeDefaultWhat it does
stepTimeoutMsnumber30000Default step and hook timeout. 0 turns it off.
scenarioTimeoutdurationTime budget per scenario attempt, such as '2m'.
runTimeoutdurationTime budget for the whole run, such as '30m'.
retryobject{ scenario, delay, backoff, workerCrash, on, failOnFlaky }. See below.

A duration is a number of milliseconds or a string such as '500ms', '2s', '1m'.

retry

KeyWhat it does
scenarioExtra attempts for a failed scenario.
delay, backoffWait between attempts, and the factor it grows by.
workerCrashRetries on a fresh process after a worker crash.
onOnly retry errors that match. An entry matches the error name exactly, the message as a substring, or a regular expression written as '/text/'.
failOnFlakyFail the run when a scenario passed only after a retry.

groups.<name>

KeyWhat it does
mode'parallel' (default), 'serial' or 'exclusive' (alone in the run).
workersThe most members running at once.
dependsOnGroups that must finish first.
onDependencyFailure'skip' (default) or 'run'.
priorityLower starts first.
locksLocks every member holds.
matchA tag expression that adds scenarios to the group.
retry, retryMembersRe-run the whole group up to n times. 'all' (default) or 'failed' members.
scenarioRetryDefault scenario retry for members.
timeoutTime budget for one attempt of the group.

Output

OptionTypeDefaultWhat it does
reportersarraySee Reporters.
logLevel'debug', 'info', 'warn', 'error', 'silent''info'Console log level. Events always contain every log.
historyboolean or { dir, keep }true keeps the last 50 runs in .bddr/history. Dry runs are never recorded.
validationobject{ allowedTagKeys: string[] } for tag checks in bddr validate.

profiles

profiles maps a name to a partial set of the options above. It cannot be changed with --set. See Profiles and --set for how profiles merge.
