bddr / Orchestration

Dependencies

Use a dependency when one test really needs another to have finished first, for example a scenario that uses an account created by an earlier one.

Depend on a scenario

Give the scenario you depend on an id with @id:, then point at it with @dependsOn:.

"Cancel the order" starts only after "Create an order" has passed. If it failed or was skipped, "Cancel the order" is skipped too, and so is anything that depends on it.

Ids

Without @id: a scenario gets an id from its file and its name, such as features/orders.feature::create-an-order. Add @id: when other scenarios point at it, so renaming the scenario does not break them. For an outline row the id is name[1], name[2] and so on. Pointing at name depends on every row.

Soft dependencies

A soft dependency orders the scenarios but does not skip anything when the earlier one fails.

Depend on a group

This scenario waits for every member of the setup group. You can also set dependsOn on the group in the config, which gives every member the same dependency. See Groups.

Order whole features

When an entire feature file needs another file to have run first, tag the feature with @requires: and the path of the file. Every scenario in the tagged feature then waits for every scenario in that file.

The path is read relative to the tagged file's folder, then relative to the project root, then as the end of a path (setup.feature finds features/shop/setup.feature if only one file ends that way). If two files match, bddr stops and asks for more of the path. A file cannot require itself, and two files cannot require each other. Put @requires on a single scenario or rule to limit it to that part of the file, and add :soft to wait without being skipped when the required file fails. File names with spaces are not supported in a tag.

What happens when a dependency fails

Dependency kindWhen the dependency does not pass
@dependsOn:idThe scenario is skipped. The skip cascades to anything that depends on it.
@dependsOn:id:softThe scenario still runs.
@requires:file.featureEach scenario in the tagged feature is skipped when any scenario in the required file does not pass. With :soft they still run.
Group dependsOnThe default is onDependencyFailure: 'skip'. Set 'run' to run anyway, as a reporting group would.

Run one scenario and what it needs

When you select a scenario with -t, a name, or file:line, bddr adds the scenarios it depends on, including the files it requires, even from other files. Add --no-deps to run only what you selected.

Pass data to a later scenario

A scenario can export a value, and a scenario that depends on it can read it. The value is copied, and it works across worker processes.

Add the dependency

ctx.from(id) throws if that scenario has not finished. If you see that error, add @dependsOn: for it.

Check the plan

bddr reports unknown ids, unknown groups and cycles such as a -> c -> b -> a before anything runs, and exits with code 2. npx bddr plan --plan-format mermaid prints the dependency graph as a Mermaid diagram you can paste into a wiki. The HTML report shows the same graph after a run.
