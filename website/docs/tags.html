bddr / Running

Tags and selection

Tags are how you choose what runs and how it runs. Your own tags, such as @smoke, select scenarios. bddr's tags, such as @retry:2, change behaviour.

Select scenarios

You wantCommand
A tag expressionnpx bddr -t "@smoke and not @wip". Operators: and, or, not, parentheses.
A name patternnpx bddr --name "refund|cancel". A regular expression on the scenario name.
A file, folder or globnpx bddr features/checkout, npx bddr "features/**/*.feature"
One scenario by linenpx bddr features/checkout.feature:12
What failed last timenpx bddr --rerun-failed reports/events.ndjson

The config tags are combined with -t using and. When you select a scenario, the scenarios it depends on are added automatically. Add --no-deps to turn that off. npx bddr list shows what a selection would run.

Your own tags

Any other tag is yours. @smoke, @ui and @api select. A @key:value tag becomes metadata: @owner:payments is ctx.scenario.meta.owner.

Keep tags tidy

Typos in tags are silent: @smoek selects nothing. List the keys your project allows, and bddr validate reports the rest.

The tags in the table above are always allowed.
