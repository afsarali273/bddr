Profiles and --set

A profile is a named set of options, such as ci or smoke. For one-off changes, --set overrides any option without editing the config file.

Profiles

A profile is merged over the base config. Later wins, with these exceptions:

  • tags are combined with and. The profile above runs (not @wip) and (@smoke).
  • params, groups and retry are merged key by key.
  • Every other option, such as reporters, is replaced.

A profile also picks the data folder: -p qa reads data/qa/file first. See Data files. An unknown profile is a usage error that lists the profiles that exist.

--set: override anything for one run

  • The part before = is a path into the config. Dots go deeper.
  • The value is read as JSON when it can be: numbers, true, false, arrays, objects. Anything else is text.
  • --set repeats.
  • A --set replaces the whole value at that path. Setting reporters replaces the whole list.
  • Top-level names are checked: --set wokers=6 is a usage error that lists the valid names.

Quoting

Quote values that contain [, ], {, } or quotes. On macOS and Linux use single quotes around the whole argument. In PowerShell use double quotes and escape inner ones: --set "groups.api.dependsOn=[\"setup\"]".

-D: parameters for steps

Each -D key=value sets ctx.params.key. The plugins read their own overrides from here, such as browser, headed, baseURL and token.

Which wins

  1. A tag on the scenario, such as @retry:3, beats everything.
  2. Then the group's setting, such as groups.x.retry.
  3. Then a command-line flag such as --retry 1, --set or -D.
  4. Then the profile, then the base config.

Flags that have a matching option, such as -w, -t and -r, win over the config file the same way --set does.
