bddr / Running

Command line

bddr is a single command with a few sub-commands. run is the default, so npx bddr alone runs your suite.

Commands

CommandWhat it does
bddr [run] [paths...]Run scenarios. Paths can be files, folders, globs or file:line.
bddr list [paths...]List the selected scenarios with their ids and tags, without running.
bddr plan [paths...]Show the execution plan: groups, dependencies, locks. Runs nothing. See Groups.
bddr validate [paths...]Static checks: parse errors, duplicate ids, undefined and ambiguous steps, unused step definitions and unmatched hooks.
bddr snippets [paths...]Print ready-to-paste code for every undefined step.
bddr report events.ndjson...Build reports from event files. Several files are merged and later runs win.
bddr history [--top n]The flakiest and slowest scenarios from the recorded history.
bddr docs [paths...]Build the living documentation page. See Living documentation.

In a project that uses bddr, run them with npx bddr. The full option list is in CLI options.

Everyday runs

Check before you run

list does not load your step code, so it cannot find undefined steps. Use --dry-run or validate for that. Add --fail-on-warnings to validate to fail a CI job on warnings.

Choose reporters

Each -f adds a reporter. See Reporters.

Exit codes

CodeMeaning
0Every scenario passed.
1A scenario failed. With the default strict mode, pending, undefined and ambiguous steps fail the run too.
2A usage, configuration or parse error. Nothing ran.
130Interrupted with Ctrl + C, after cleanup and writing the reports.

Paths on Windows

Use the same commands in PowerShell. Quote tag expressions with double quotes, as above. In cmd.exe use double quotes for everything.

Tip

Add scripts to package.json so the team types less: "test": "bddr", "test:smoke": "bddr -t @smoke", "test:ci": "bddr -p ci".
