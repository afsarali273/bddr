bddr / Writing tests

Class steps and page objects

If you prefer classes over functions, mark a class with @Steps() and decorate its methods. Page objects are plain classes that ask for what they need with inject().

A step class

  • Method arguments are the captured values only. The context is not passed in; ask for it with inject(CONTEXT).
  • Decorators take the same options as the function form: { timeoutMs, retry, concurrent, tags }.
  • The steps file only needs to be in the config's steps glob.

Page objects

A class you inject is created once per scenario, and every step class that injects it gets the same instance. If it has a dispose() method, bddr calls it when the scenario ends.

Constructors

When a class asks for an asynchronous fixture that is not ready yet, bddr creates the fixture and constructs the class again. Keep constructors to setting up fields, which is normal anyway.

Hooks in classes

Decorators also work for hooks: on static methods for every level, and on instance methods for Before, After, BeforeStep and AfterStep.

Classes or functions?

They match steps the same way and can live in the same project. Functions are shorter for small suites. Classes keep related steps and their page objects together when a suite grows. The examples/playwright-showcase and examples/selenium-showcase projects both use classes with page objects.
