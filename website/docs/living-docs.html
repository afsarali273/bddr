bddr / Reports

Living documentation

Your feature files already describe what the product does. The docs command presents them as a readable page, so people who do not run tests can browse them.

Build it

bddr docs [paths...] [options]

Writes one offline HTML page.

-o file
Where to write it. Default reports/living-docs.html.
--results file
An NDJSON event file. Repeatable. Colours each scenario by its result. Without it, the latest recorded history run is used.
--title text
The page title.

What you get

  • A folder tree for navigation. Each folder's README.md is its introduction, and its first heading is the folder's title.
  • Features with their descriptions, scenarios, steps, data tables and doc strings, and tags as chips.
  • Search across all of it.
  • With results, scenarios are coloured and each folder shows a roll-up.

Markdown

README files use a small, safe subset of Markdown. Links are limited to http, https, mailto and relative paths.

Publish it

The page is one file. Publish it as a CI artifact, or copy it to any static host after each run on your main branch, so the documentation always matches the tests.
