bddr / Running

Configuration

The config file holds everything that stays the same between runs. Everything in it can be overridden for one run from the command line.

The file

bddr looks for bddr.config.ts (or .mts, .js, .mjs, .json) in the folder you run it from. Use -c path to pick another. All paths and globs in it are relative to the config file's folder.

defineConfig adds type checking and completion. It returns what you give it.

Every option, with its type and default, is in Config options.

Defaults when you leave things out

  • features: features/**/*.feature and features/**/*.feature.md
  • steps: steps/**/*.{ts,js,mjs} and features/**/*.steps.{ts,js,mjs}
  • workers: 1. pool: 'inline'. strict: true.

Parameters for your steps

params values are available as ctx.params. -D key=value overrides them for a run.

Note

The name params is reserved. Do not use it as a fixture name.

Check the result

To see what a run would use after profiles and overrides, run npx bddr plan or npx bddr list with the same options. Both read the same config.
