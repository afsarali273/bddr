Writing your own plugin

A plugin is a function that registers things when the process starts. Start with a file inside your project. Move it to a package when other projects need it.

The smallest plugin

Steps now ask for it: Given('a user exists', async ({ db }) => { /* ... */ }).

What setup can do

setup(options) runs once in every process, before step files load. Inside it you can call the same functions as in a step file:

  • defineFixture: named resources with a scope and cleanup. See Fixtures and inject().
  • BeforeAll, BeforeWorker, Before, After and the other hooks.
  • Given, When, Then: steps that every project using the plugin gets.
  • defineParameterType: shared parameter types.

Where names come from

In pluginsResolved as
'@acme/bddr-db'A package, looked up from the config folder.
'./support/db.plugin.ts'A file, relative to the config.
['name', { options }]The same, with options passed to setup.
myPlugin({ options })A plugin object, as the shipped plugins export.

The package or file must export the result of definePlugin as its default export. To get the myPlugin({ ... }) style, export a small function that returns the plugin with its options.

Guidelines from the shipped plugins

  • Do not depend on the library you wrap. Make it a peer dependency. Load the project's copy with createRequire from the working directory, so two copies never clash.
  • Start nothing until asked. Fixtures are created on first use. Put expensive resources in worker scope.
  • Read overrides from ctx.params, so -D key=value works.
  • Attach evidence. Use ctx.attach or ctx.log.image for screenshots and call logs. Attach on failure by default.
  • Test with a fake. The shipped plugins test against a fake of the library, so the tests need no browser. Add a test that makes the fake behave like the real library where it matters.

Not yet available

Plugins cannot yet add reporters, data loaders, retry analyzers or plan modifiers. These extension points are planned. See docs/STATUS.md.

For a complete example read plugins/axios/src/index.ts. It is a single file with options, three fixtures, a call log and an offline test.
