bddr / Introduction

Coming from Cucumber.js

Your feature files do not change. The step code changes shape a little: bddr passes a context instead of using this, and hooks have more levels.

What stays the same

  • Feature files. Gherkin, Background, Scenario Outline, Rule, tags, data tables and doc strings work as before. bddr parses with the Cucumber Gherkin parser.
  • Step patterns. Cucumber Expressions and regular expressions, with {int}, {string} and custom parameter types.
  • Tag expressions. -t "@smoke and not @wip".
  • Reports. Cucumber JSON and Cucumber Messages are available as reporters, next to JUnit XML and HTML.

A step, before and after

There is no this and no World class. Ask for the fixtures you need in the first parameter. The page fixture comes from the Playwright plugin.

Move in four steps

  1. Keep the feature files

    Point features in the config at them. Run npx bddr validate to see what needs attention.

  2. Change the import

    Replace @cucumber/cucumber with @bddr/runtime. Hooks and defineParameterType keep their names.

  3. Replace this

    Take ctx or destructured fixtures as the first parameter. Move World properties to ctx.state or to fixtures.

  4. Add the plugin for your browser or API library

    See Playwright, Selenium and axios.

No codemod yet

A tool that rewrites this into context calls is on the list but does not exist. Plan to edit step files by hand. Arrow functions work in bddr, which makes the edit mostly mechanical.

What you gain

Groups, dependencies, locks, serial features, retries and quarantine, sharding and the process pool. See Why bddr.
