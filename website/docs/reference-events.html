Event stream (NDJSON)

Everything that happens in a run is an event. The NDJSON reporter writes them one JSON object per line. All other reporters, the debugger and the history tooling read only this stream.

Write it

Each line has a ts (milliseconds since the epoch) and a type. The stream is at schema version 1. Adding an optional field is not a breaking change. Renaming or removing a field or an event type bumps the version.

Event types

TypeFields
runStartedrunId, schemaVersion, framework, runtime, dryRun
specParseduri, featureName, scenarioCount, errors
planReadyscenarios (id, name, uri, line, tags, steps, example row, groups, dependencies), workers, groups
workerStartedworkerId, pid, startupMs
groupStarted, groupFinishedgroup, attempt, and status when finished
groupRetryinggroup, attempt, scenarioIds
featureStarted, featureFinisheduri, name, and status when finished
hookStarted, hookFinishedhookId, hookName, level, kind, scenarioId, and status, durationMs, error when finished
scenarioStartedscenarioId, attempt, workerId, and on the first attempt waitedForMs (how long the scenario was ready but held back by a free worker, a lock, a group cap or @exclusive)
stepStartedscenarioId, stepId, keyword, text, line
stepFinishedscenarioId, stepId, status, durationMs, error, definition (pattern, location), snippet for undefined steps, mode and attempts for repeated or retried steps
stepAttemptFinishedscenarioId, stepId, attempt, of, mode, status, durationMs
attachmentscenarioId, stepId, name, mediaType, encoding (identity or base64), body
logscenarioId, message, level, source (user or bddr), data, attempt, attachment
scenarioFinishedscenarioId, attempt, status, durationMs, error, reason, willRetry, flaky, quarantined
runFinishedsuccess, summary (scenario and step counts per status, durationMs, flaky, quarantined, retried), error

A status is one of passed, failed, skipped, pending, undefined or ambiguous. An error has message and optional name and stack.

Use it

  • Re-run what failed: npx bddr --rerun-failed reports/events.ndjson.
  • Merge runs: npx bddr report a.ndjson b.ndjson -f html:reports/merged.html. Later runs win.
  • Colour the living documentation: npx bddr docs --results reports/events.ndjson.

Compatibility

The events map one to one onto Cucumber Messages. -f messages produces them. Scenarios generated from @data files are left out, and hooks are not emitted as hook messages yet.
