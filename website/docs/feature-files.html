bddr / Writing tests

Feature files

A feature file describes behaviour in plain language. Each scenario becomes one test. bddr reads standard Gherkin, so existing files work.

The shape of a file

  • Feature groups scenarios. The text under it is a description for readers.
  • Background steps run before every scenario in the feature.
  • Scenario is one test. Scenario Outline with Examples is one test per row.
  • Rule groups scenarios inside a feature. Tags on a rule apply to its scenarios.

Other languages

Set language in the config to write keywords in another language. Markdown files with Gherkin inside (.md) also work as specs.

Tags

Tags start with @ and sit on the line above a Feature, Rule, Scenario or Examples block. A scenario also has the tags of its feature and rule. Tags that look like @key:value are kept as metadata.

A step can read it as ctx.scenario.meta.owner. Select scenarios with a tag expression:

See Tags and selection for the list of tags bddr understands.

Scenario ids

Every scenario gets a stable id. Dependencies, reruns and merged reports use it.

  • With @id:add-single the id is add-single.
  • Without it the id is the file and the scenario name, such as features/basket.feature::add-a-single-product.
  • Outline rows add the row number: add-single[1].

Outline ids use the name before the placeholders are filled in, so changing the example values does not change the ids. List ids with npx bddr list.
