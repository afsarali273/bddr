bddr / Reference

CLI options

The complete list, as printed by bddr --help for version 0.1.0. Options apply to every command that makes sense for them.

Commands

CommandPurpose
bddr [run] [paths...]Run scenarios. Paths are files, folders, globs or file:line.
bddr list [paths...]List scenarios with ids and tags, without running.
bddr snippets [paths...]Print code for every undefined step.
bddr steps [--json]List every step, hook and fixture the support code registers, with file:line. --json prints the step catalogue for editors and tools.
bddr validate [paths...]Static checks on specs, plan, steps and hooks.
bddr plan [paths...]Show groups, dependencies and locks. Options --plan-format text|json|mermaid and --explain <scenario id>.
bddr report <events.ndjson...>Build reports from event files. Several files are merged and later runs win.
bddr history [--top n]The flakiest and slowest scenarios. Needs history: true.
bddr docs [paths...]Living documentation. Options -o, --results (repeatable; without it, the last recorded run or reports/events.ndjson is used), --title.
bddr migrate [dir] [--write]Update a project that used the old name bddx: @bddx/* imports, BDDX_* variables, bddx.config.* and .bddx/. Shows what would change unless you pass --write.

Selection

OptionWhat it does
-t, --tags <expr>Tag expression, such as "@smoke and not @wip". Combined with the config tags using and.
--name <regex>Only scenarios whose name matches.
--no-depsDo not add the dependencies of selected scenarios.
--rerun-failed <file>Only scenarios that did not pass in an events file, plus their dependencies.
--shard <i/n>Run shard i of n. Also works with plan. See Sharding in CI.

Configuration

OptionWhat it does
-c, --config <file>Config file. Default: bddr.config.{ts,mts,js,mjs,json} in the current folder.
-p, --profile <name>Use a profile from the config.
-s, --set <path=value>Override any config value. Repeatable. See Profiles and --set.
-D, --define k=vSet ctx.params.k. Repeatable.

Running

OptionConfigWhat it does
-w, --workers <n>workersScenarios running at once. Default 1.
--pool <kind>poolinline (default) or process.
--timeout <ms>stepTimeoutMsDefault step and hook timeout.
--run-timeout <dur>runTimeoutTime budget for the run, such as 30m.
--fail-fastfailFastStop after the first failed scenario.
--no-strictstrictPending and undefined steps do not fail the run.
--dry-runMatch steps and report undefined ones. Run nothing.

Retries

OptionConfigWhat it does
-r, --retry <n>retry.scenarioRetry failed scenarios up to n times.
--worker-crash-retry <n>retry.workerCrashRetry on a fresh process after a worker crash.
--fail-on-flakyretry.failOnFlakyFail the run when a scenario passed only after a retry.

Output

OptionWhat it does
-f, --format <spec>Add a reporter: console, progress, html[:file], junit[:file], ndjson[:file], cucumber-json[:file], messages[:file]. Repeatable.
--log-level <level>debug, info (default), warn, error or silent.
--fail-on-warningsWith validate: exit 1 when warnings are found.

Developing

OptionWhat it does
--watchRun, then re-run on file changes. See Debugging and watch mode.
--debugPause after a failing step.
--debug-stepPause before every step.
--inspect [port]Open the Node inspector, default port 9229, and wait for a debugger.
-h, --help; -v, --versionHelp and version.

Exit codes

0 passed, 1 failed, 2 usage, configuration or parse error, 130 interrupted.
