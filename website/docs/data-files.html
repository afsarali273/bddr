bddr / Writing tests

Data files (CSV, JSON, Excel)

Put test data in a file, tag a scenario with @data, and bddr runs the scenario once per row. Each row gets its own id and its own line in the report.

A scenario from a CSV file

The column names become the placeholders. This runs three scenarios. Files are looked up in the config's dataDir.

Fill an Examples block

The Examples block keeps its header and takes its rows from the file. @dataField:item=product says that the placeholder item comes from the column product.

The tag in full

@data:<file>[#selector][?col=val&rows=1-3,7]

PartMeaning
fileCSV, TSV, JSON, YAML or XLSX, by extension. XLSX needs the optional exceljs package: npm i -D exceljs.
#selectorFor JSON and YAML, a dotted path to the array, such as #data.users. For Excel, the sheet name.
?col=valKeep rows where the column equals the value.
rows=1-3,7Keep these rows by their number in the file, header not counted.
@dataField:placeholder=columnMap a placeholder to a different column.

Row numbers count before filtering, so a filter never changes the id of a row. A data error, such as a missing file, is reported as a parse error on the tag line and the run exits with code 2.

A different folder per profile

With a profile, bddr tries <dataDir>/<profile>/file first. In examples/basic, npx bddr run -p qa reads data/qa/prices.csv instead of data/prices.csv.

Ids for data rows

A row's id is the scenario id followed by the file and the row number, such as [prices.csv#2]. Use it with @dependsOn like any other id.
