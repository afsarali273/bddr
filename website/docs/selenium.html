Selenium

The Selenium plugin works the same way as the Playwright plugin. Steps ask for a driver, and bddr starts a fresh browser session for each scenario and quits it afterwards.

Install

Not on npm yet

bddr is not published to the npm registry yet, so it is installed from your clone with file: paths. Once it is published, run npm i -D @bddr/selenium plus the library instead, and this note will go away.

Selenium Manager comes with selenium-webdriver and finds or downloads the driver for Chrome, Firefox and Edge. You need the browser itself installed. selenium-webdriver 4.x needs a recent Node.js: use Node 22 or 24.

Configure

Add import '@bddr/selenium'; to one support file so ctx.driver, ({ driver }) and inject('driver') are typed.

Use it in steps

Warning

A helper that reads ctx.selenium or ctx.driver inside its body is not seen by bddr. Destructure the fixture in the step and pass it on, or use await ctx.fixture('selenium').

Fixtures

NameScopeWhat you get
seleniumworkerThe selenium-webdriver module: By, Key, until, Capabilities.
driverscenarioA fresh WebDriver, one browser session per scenario attempt. A screenshot is taken at the end, then the session quits.
openscenarioawait open('/login'): driver.get() relative to baseURL.
waitscenarioawait wait(until...): driver.wait() with waitTimeoutMs as the default timeout. Returns the element for element conditions.
newDriverscenarioawait newDriver({ browser: 'firefox' }) gives a second session, for another user or browser. It quits after the scenario.

Selenium has no browser and context split, so every session is a real browser process. A scenario that uses none of these starts nothing.

Options

OptionDefaultWhat it does
browser'chrome''chrome', 'firefox', 'edge' or 'safari'. -D browser=firefox overrides.
headlesstrue-D headed=true shows the browser. Safari has no headless mode.
argsExtra browser arguments such as '--lang=de' or '--incognito'.
capabilitiesExtra W3C capabilities. Vendor args are combined with the ones above.
serverA remote endpoint such as a Selenium Grid or a cloud provider: 'http://grid:4444'. -D server= overrides.
baseURLBase of open('/path'). -D baseURL= overrides.
windowSize{ width, height }.
implicitWaitMs, pageLoadTimeoutMs, scriptTimeoutMsSelenium'sSession timeouts.
waitTimeoutMs10000Default timeout of wait(...).
screenshot'only-on-failure''off', 'on' or 'only-on-failure'.
reuseSession'off''serial' makes every @serial feature share one browser session.

The plugin uses your project's own copy of selenium-webdriver, so import { until } from 'selenium-webdriver' in your code and the driver share one copy. Selenium checks wait conditions with instanceof, which fails with two copies.

One browser session for a whole feature

@reuseSession needs @serial on the feature. @freshSession on a scenario opts out. The browser quits when the feature ends.

Run it

What has been verified

The showcase's 33 scenarios pass on Firefox. Chrome, Edge, Safari and a remote Grid have not been run yet.

See plugins/selenium/example for an offline project and examples/selenium-showcase for 33 scenarios against public sites.
