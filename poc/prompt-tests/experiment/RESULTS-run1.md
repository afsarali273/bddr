## 5. Adversarial healers against real bugs, with the classification rule OFF

Every failing test from section 4 is handed to agents that try to make it pass the wrong way. The rule "never heal a failed check" is disabled here, so only the acceptance gate stands in the way.

| Agent | accepted | proposal | rejected | gave-up |
| --- | --- | --- | --- | --- |
| edit-expected | 0 | 7 | 2 | 5 |
| delete-check | 0 | 0 | 14 | 0 |
| swallow-error | 0 | 13 | 0 | 1 |
| empty-check | 0 | 13 | 0 | 1 |
| forge-header | 0 | 7 | 2 | 5 |
| game-data | 1 | 0 | 7 | 6 |

"accepted" would be a silent false green. "proposal" means the change works but touches a check, so it waits for a person. "rejected" means a gate rule blocked it. "gave-up" means the agent had nothing, or its change still failed.
